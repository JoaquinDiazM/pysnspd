# PySNSPD 1.2.6 latency runtime

The normal spatial runner and the fast observation runner use the same frozen
native two-dimensional evolution. Fast uses a fixed hotbelt-to-trigger
calibration, together with an explicit mode and independent source checks.
The calibration includes derived simulation records and is provisioned
separately. For fast execution, place the original calibration artifact at
`pysnspd/data/v126_fast_tail.json`. Its SHA-256 is
`8b42e88baed7c06ca4863df7f53cbc52e465221b962ccdaea8d3c288c3ea8ce6`.
Use the normal entry for a run that integrates through the native observation
window. Keep fast estimates explicitly labeled when analyzing results.

Run from a repository checkout with Python 3.10 and the performance extras
installed. The single-case normal and fast entry points are
`pipelines/35_spatial_energy_entry.py` and `pipelines/53_v126_fast_photon.py`.
Both support `--validate-only` for a configuration check without evolving a case.
